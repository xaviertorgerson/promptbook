# Plan readiness

## Problem

A plan handed to agents with gaps is executed faithfully, gaps included. Tasks too large for one
session stall; tasks that silently touch the same files collide; tasks that trace to no requirement
are scope creep; requirements no task covers are discovered missing at release.

## Practice

**Execution plan (stage 8).** Decompose into task files. Each task has:

| Field | Rule |
|---|---|
| `depends_on` | tasks that must be merged first; the graph is the schedule |
| `touches` | path globs it will edit; disjoint globs may run in parallel, overlapping ones form a lane |
| `size` | XS–XL; larger than one focused session is split before `ready` |
| `risk` | low/medium/high; drives evaluator strength and whether the plan needs a human gate |
| `inputs` | the exact docs and sections to read (section-level, not whole files) |
| `evaluator` | which checks judge it (tests, browser, fresh review) |
| `budget` | turn and spend caps for one run |
| criteria | `AC-n`, each citing at least one `REQ-n`/`NFR-n` |

Open questions that block a task keep it out of `ready`. The planner does not guess.

**Readiness (stage 9).** A generated report, not a judgement call. The plan is ready when:

- the trace graph is complete: BRIEF → PER → CUJ → REQ/NFR → UX (user-facing CUJs) → TASK.AC;
- there are no orphans: no persona without a journey, no journey without a requirement, no
  requirement without a task, no task citing nothing;
- every one-way ADR is accepted, and the walking skeleton is the root of the graph where required;
- no two parallel-eligible tasks have overlapping `touches`;
- no task is larger than the size cap or has an unanswered blocking question.

A human approves the spec at readiness. Tasks then move to `ready` and execution starts on events.

## Evidence

- 2026-09-23 · practice · agentic-template: tasks larger than one session are split before `ready`;
  a task with an open blocking question cannot be `ready`; claims are compare-and-swap commits
  ([workflow.md](https://github.com/xaviertorgerson/agentic-template/blob/master/docs/workflow.md)).
- 2026-09-23 · practice · its loop dispatches the highest-priority ready task whose dependencies are
  merged ([loop.mjs](https://github.com/xaviertorgerson/agentic-template/blob/master/scripts/loop.mjs)).
- 2026-10-02 · vendor · Kiro builds a dependency graph and runs independent tasks in concurrent waves
  ([Kiro](https://kiro.dev/docs/specs/)).
- 2026-03 · self-reported · ICM's stage contracts name the exact files and sections to load
  ([arXiv 2603.16021](https://arxiv.org/html/2603.16021)).
- 2026-10-12 · recommendation · the research report "Agentic orchestration patterns 2026" proposed
  adding `touches`, `risk`, `inputs`, `evaluator`, `budget` and `sessions` to the current task
  frontmatter ([_TASK-TEMPLATE.md](https://github.com/xaviertorgerson/agentic-template/blob/master/specs/_TASK-TEMPLATE.md))
  so that single-writer and routing become checkable.

## Contracts used

`task`, `readiness-report` (`specs/<epic>/readiness.md`, generated by `tools/validate.mjs`; the
plan rules `overlapping-tasks-ordered`, `skeleton-is-root`, `one-way-door-decided`,
`ready-task-unblocked`, `task-size-fits` block readiness), `state-machines/workflow.yaml`
(`spec-draft` → `ready`).

## Anti-patterns

- Readiness judged by reading the plan instead of running the validator.
- `touches` left empty so everything looks parallel.
- Tasks sized by hope; the split happens after the first stall.
- Inputs listing whole directories.
- A plan approved with orphans "to fill in later".

## Revisit when

The validator's orphan and overlap checks stop finding anything across several epics (the stage can
be folded into the planner), or parallel runs show collisions the `touches` check missed.
